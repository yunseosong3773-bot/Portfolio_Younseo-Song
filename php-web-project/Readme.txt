1. 본 웹 애플리케이션의 보안 취약점 대처를 위한 설계 고민 및 구현
========================================================================
본 프로젝트는 산업보안학과 전공자로서 실제 웹 애플리케이션 개발 환경에서 
발생할 수 있는 치명적인 기술적/인적 보안 취약점을 식별하고, 이를 시큐어 코딩 
및 유기적 UI/UX 분기로 방어하기 위해 다음과 같은 깊은 고민을 거쳐 기능을 구현했습니다.

(1) SQL Injection 취약점에 대한 고민과 방어 구현
    - [보안적 고민] : 
      공격자가 로그인 폼의 텍스트 박스에 `' OR '1'='1` 과 같은 악의적인 SQL 구문을 
      주입할 경우, 백엔드 쿼리의 논리 구조가 왜곡되어 데이터베이스 내부의 유저 정보를 
      무단 탈취하거나 인증을 무력화하고 무단 진입할 수 있는 심각한 위험이 존재했습니다.
    - [기능 구현 대응] : 
      이를 원천 차단하기 위해 사용자가 입력한 모든 POST 데이터 값(`user_id`, `pwd`)이 
      SQL 구문으로 해석되지 않도록 전처리하는 고민을 했습니다. 
      `db_connect.php`와 연동되는 모든 로그인 처리 초입부에 `mysqli_real_escape_string()` 
      함수를 적용하여 특수문자를 안전하게 이스케이프 필터링했습니다. 이에 더해, 텍스트 긁어오기 
      등에서 발생할 수 있는 보이지 않는 양끝 공백 오타를 제거하기 위해 `trim()` 구조를 
      중첩 설계함으로써 주입 공격 벡터(Attack Vector)를 완벽하게 무력화했습니다.

(2) 데이터베이스 탈취 시 패스워드 평문 노출 취약점에 대한 고민과 방어 구현
    - [보안적 고민] : 
      만약 웹 서버나 데이터베이스 관리자 페이지(phpMyAdmin)가 물리적/논리적으로 탈취당할 경우, 
      수강생들의 비밀번호가 평문(Plain Text) 그대로 노출되어 타 사이트 연쇄 해킹(Credential Stuffing) 
      등 이차 피해로 이어질 수 있다는 문제의식을 가졌습니다.
    - [기능 구현 대응] : 
      데이터의 기밀성(Confidentiality)을 확보하기 위해 비밀번호를 원초적 텍스트로 보관하지 않고, 
      PHP 내부 최고 수준의 보안 암호화 함수인 `password_hash()`의 `PASSWORD_BCRYPT` 엔진을 
      도입했습니다. 복호화가 불가능한 단방향 솔팅 해시 구조를 취하여 DB를 열어보더라도 난수형 
      암호문($2y$10$...)만 보이도록 설계했습니다. 로그인 검증 시에도 오직 `password_verify()`만을 
      사용하여 해시값 간 대조가 안전하게 이루어지는 무결성 체계를 사수했습니다.

(3) 초기 기본 비밀번호(Default Password) 방치 취약점에 대한 고민과 방어 구현
    - [보안적 고민] : 
      시스템 구축 및 초기 학사 명부 일괄 세팅 시, 관리자와 30명의 수강생에게 '1234'라는 
      단순한 초기 기본 비밀번호가 일괄 할당되었습니다. 만약 사용자가 귀찮다는 이유로 이 값을 
      그대로 방치하고 스케줄러를 이용한다면 무작위 대입 공격(Brute Force)이나 사회공학적 기법에 
      의해 계정이 너무나 쉽게 탈취될 수 있다는 보안적 취약점을 식별했습니다.
    - [기능 구현 대응] : 
      사용자에게 비밀번호 변경을 강력하게 강제·유도하는 인터셉트(Intercept) 방어 기능을 
      백엔드(`login_process.php`)에 구현했습니다. 유저 권한과 상관없이 로그인에 통과한 데이터가 
      초기값인 `1234`임이 확인되면 즉시 브라우저 화면에 보안 경고 컨펌창(`confirm`)을 팝업시킵니다. 
      여기서 사용자가 [확인]을 누르면 일반 학생은 수강생 전용 마이페이지(`member_page.php`) 하단의 
      비밀번호 수정 섹션으로, 행정 관리자는 `admin_page.php` 하단의 마스터 암호 변경 폼으로 각각 
      권한에 맞춰 다이렉트 자동 워프(Warp) 리다이렉션 되도록 정밀 동선을 구현했습니다.
    - [UPDATE 시 호환성 고민] : 
      더불어 사용자가 변경 창에서 새로운 패스워드를 입력할 때는, 로컬 서버 가상 환경의 
      문자열 규격(VARCHAR 길이 부족으로 인한 해시 유실 현상) 오류를 사전에 예방할 수 있도록 
      DB users 테이블의 `pwd` 길이를 `VARCHAR(255)`로 넉넉하게 확장 개편해 두었습니다. 
      이로 인해 웹 폼 화면을 통해 변경된 새 암호는 사용자의 로컬 환경 고유 솔트를 완벽하게 반영하여 
      단 한 글자의 깨짐도 없이 실시간 UPDATE 쿼리를 타고 DB에 정식 규격으로 박히게 되며, 
      이후 재로그인 시 100% 정상 통과되도록 데이터 무결성을 보장했습니다.

2. 가상 가동 서버 환경 구성 및 필수 설정 (APM 구동 특이사항)
========================================================================
본 웹 애플리케이션은 수업 시간에 다룬 기본 APM 기능을 바탕으로 구축되었으나, 
정석 보안 규격인 Bcrypt 단방향 해시 알고리즘의 무결성 작동과 채점관 환경에서의 
실행 호환성을 보장하기 위해 다음과 같은 필수 서버 구성 요건을 반영하였습니다. 
MAMP 및 APM 가동 시 참고를 부탁드립니다.

(1) PHP 최소 엔진 버전 요구 규격 (Version 5.5 이상 필수)
    - 구현된 패스워드 암호화 및 검증 검사 함수인 `password_hash()`와 `password_verify()`는 
      PHP 5.5 버전 이상부터 고유 코어로 공식 지원되는 내장 보안 보안 API입니다. 
    - 따라서 본 소스코드가 런타임 에러(Fatal Error: Call to undefined function) 없이 
      정상 구동되기 위해 채점 환경의 PHP 버전이 5.5 이상(본 개발 환경은 MAMP PHP 8.x 기반)
      임을 확인하고 세팅해야 합니다.

(2) MySQL 데이터베이스 `users` 테이블 구조 변경 (VARCHAR 길이 확장)
    - 수업 시간에 다룬 일반적인 평문 패스워드 저장 방식은 보통 `VARCHAR(15~20)` 규격을 사용합니다.
    - 하지만 Bcrypt 해시 알고리즘을 거쳐 나오는 난수형 암호문은 언제나 고정된 '60글자의 문자열'로 
      출력 및 변환되는 특성을 가지고 있습니다.
    - 만약 기존 베이스라인 스펙 그대로 길이를 짧게 둘 경우, 암호문의 뒷부분이 잘려 나가는 
      데이터 절단(Data Truncation) 현상이 발생하여 `password_verify()` 대조 시 100% 무조건 
      로그인 불일치(인증 실패) 오류가 터지는 구조적 취약점이 식별되었습니다.
    - 이를 해결하기 위해 백업 파일(`assign_db.sql`) 내 `users` 테이블의 `pwd` 컬럼 데이터 타입을 
      `VARCHAR(255)`로 대폭 확장 구성해 두었습니다. 채점관 환경에서 신규 회원가입 및 관리자 
      비밀번호 실시간 UPDATE 동작을 수행할 때 암호문 유실 없이 안전하게 호환 처리됩니다.

3. 데이터베이스 쿼리(JOIN / Subquery) 소스코드 내 위치
========================================================================
본 프로그램은 데이터베이스 내부의 유기적인 연동과 관리 관제 뷰의 정밀성을 확보하기 위해 
아래와 같이 고급 SQL 구문을 사용하였으며, 실제 코드 내 위치는 다음과 같이 정확히 일치합니다.

(1) 고급 대조 JOIN 구문 적용 위치
    - 파일명 및 소스코드 내 위치 : `member_page.php` (수강생 마이페이지) - Line 12 ~ Line 15
    - 쿼리 상세 내용 :
      "SELECT u.*, t.months, t.total_count, t.remaining_count, t.expiry_date 
       FROM users u 
       JOIN tickets t ON u.user_id = t.user_id 
       WHERE u.user_id = '$user_id'"
    - 구현 목적 및 결과 출력 : 
      로그인한 수강생의 고유 식별자(ID)를 기반으로 `users` 테이블의 인적 원적 정보와 
      `tickets` 테이블의 수강권 승인 내역을 'INNER JOIN'으로 결합하여 단건 호출합니다. 
      이를 통해 마이페이지 화면 상단의 수강권 스펙(계약 기간, 잔여 횟수, 마감 디데이 등)을 
      테이블 형태로 조화롭게 매핑하여 출력하는 결과 뷰를 완성했습니다.

(2) 집계 및 통계 Subquery (내포된 서브쿼리) 구문 적용 위치
    - 파일명 및 소스코드 내 위치 : `admin_page.php` (행정 관리 센터 페이지) - Line 53 ~ Line 54
    - 쿼리 상세 내용 :
      "SELECT c.*, (SELECT COUNT(r.res_id) FROM reservations r WHERE r.class_id = c.class_id) AS app_cnt 
       FROM classes c 
       ORDER BY c.class_date ASC"
    - 구현 목적 및 결과 출력 : 
      개설된 전체 강의 목록(`classes`)을 시행 일자 순으로 순회 출력할 때, 메인 쿼리 내부에서 
      각 강의의 `class_id`를 참조하는 실시간 예약 건수를 `reservations` 테이블에서 실시간으로 
      카운트(`COUNT`)해오는 스칼라 서브쿼리(Scalar Subquery) 기법을 활용했습니다. 
      이를 통해 관리자 화면의 '현재 예약 현황' 열에 [현재 예약 인원 / 최대 정원 (3명)] 형태의 
      정밀한 수치 결과를 실시간으로 계산하여 보여주는 관제 결과를 도출했습니다.

4. 채점 기준 준수 및 핵심 요건 매핑
========================================================================
[✔] 경로 무결성 (상대경로 준수)
    - 채점관의 개발 환경 독립성을 보장하기 위해, 소스코드 내 모든 파일 참조 및
      DB 연결 경로는 절대경로(C:\...)를 완전히 배제하고 상대경로(./db_connect.php)
      체계로만 100% 구축 완료했습니다. 채점 시 코드 수정이 전혀 필요 없습니다.

[✔] HTML5 입력 폼 (다양성 요건 충족: 총 6개 양식 유기적 연동)
    1) text box : ID 입력 및 텍스트 데이터 기입
    2) password box : 비밀번호 보안 마스킹 입력 및 눈 표시(👁) 실시간 토글 구현
    3) textarea : 마이페이지 내 사전 상담 및 건의 메모 데이터 처리
    4) radio button : admin_page 내 개설 강의 타임 슬롯(오전반/오후반) 선택
    5) dropdown list (select/option) : 수강 희망 교과 자격증 종목 분류 지정
    6) HTML5 Calendar (date) : 교육 시행 일자 및 개강일 처리

[✔] 데이터베이스 무결성 규격 사수 (최소 4개 테이블, 각 20개 이상 레코드 확보)
    - 데이터 유실 및 덤프 에러를 원천 차단하기 위해 외래키(Foreign Key) 제약 조건의 
      순차적 조립을 완벽하게 검증했습니다. (제출본 내 'assign_db.sql' 파일 참조)
    - 구조 명세 마스터 테이블 목록 (총 4개 아키텍처 구조):
      1) users (회원 계정 원적 테이블) : 총 32개 정밀 레코드 탑재
      2) classes (학원 개설 강의 시간표 테이블) : 총 30개 정밀 레코드 탑재
      3) tickets (수강생 1:1 결합 수강권 배정 테이블) : 총 30개 정밀 레코드 탑재
      4) reservations (실시간 강의 예약 확정 내역 테이블) : 총 30개 정밀 레코드 탑재

[✔] 권한별 비즈니스 로직 분기 분리 (회원 전용 vs 비회원 전용)
    - 비회원(Guest) 상태: 메인 시간표 스케줄러 노출부 및 전체 개설 목록만 열람 가능, 
      실시간 예약 신청 및 개인 스펙 열람 시도 시 인증 유도 필터링 작동.
    - 회원(Student/Admin) 인증 상태: 개별 부여된 세션 식별자를 통해 수강권 횟수 차감 
      예약 프로세스 수행, 마이페이지 연동 및 행정실 총괄 관리자 스페이스 분리 작동.

5. 심미성 및 전체 웹 애플리케이션의 완성도
========================================================================
- 일관성 있는 CSS 테마 디자인: 개별 요소에 파편화된 인라인 스타일을 입힌 것이 아닌,
  통합적인 네이비 블루 및 에메랄드 그린 스킨 컬러 테마를 CSS 외부 시트로 관리하여 
  실제 교육 자격증 관제 허브와 같은 높은 심미적 UI/UX를 달성했습니다.
- 클라이언트 편의 기능 탑재: 로그인 창에서 사용자가 본인의 복잡한 암호를 오타 없이 
  확인할 수 있도록 웹 표준 눈 기호(👁) 비밀번호 가시성 토글 자바스크립트 엔진을 설계하여 
  UI 완성도를 비약적으로 끌어올렸습니다.
